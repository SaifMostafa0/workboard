## Summary

Workboard works offline in the browser but is not installable. A PWA makes the offline-first
promise tangible and closes part of the platform gap with native apps.

## Acceptance criteria

- [x] A service worker precaches the app shell and assets; the app loads offline after first visit.
- [x] A web app manifest (name, icons, theme colours) enables install on desktop and mobile.
- [x] An update flow prompts the user to reload when a new version is available.
- [x] An optional encrypted backup exports data protected by a user passphrase (Web Crypto).
- [x] Cache strategy is documented and does not break SPA deep links.
- [x] Lighthouse PWA checks pass and no performance budget regressions.

## Updates

**2026-10-28 — done**

- `public/sw.js` + `scripts/build-sw.mjs`: after `vite build`, the emitted file list (17 URLs) and a
  content hash are injected into the worker. The shell and hashed assets are precached; navigations
  are network-first with a cached `/index.html` fallback; static assets use stale-while-revalidate.
  Old versioned caches are deleted on activation.
- `public/manifest.webmanifest` (standalone, theme colour, 192/512/maskable icons) plus
  `apple-touch-icon` and `theme-color` links make the app installable. Icons are generated by
  `npm run icons` (`scripts/generate-icons.mjs`) with no image dependency.
- `src/lib/serviceWorker.ts` registers only in production builds, checks for updates hourly, and
  prompts via a dismissible banner in `Layout`; `SKIP_WAITING` + `controllerchange` reload only on
  user action so unsaved forms survive.
- Encrypted backup (`src/lib/backup.ts` + Settings): PBKDF2-HMAC-SHA256 (310k iterations) derives an
  AES-256-GCM key; each export gets a fresh salt/IV and a self-describing envelope. Import detects
  the envelope and asks for the passphrase. Attachment blobs are excluded (local-only).
- Verified with the committed `npm run pwa:check` smoke test (Playwright + production preview):
  worker activates and precaches `/` + `/index.html`, manifest and all icons return 200, and after
  the preview server is stopped a fresh navigation and a deep link (`/tasks?status=todo`) both render
  the app shell from the worker. The check caught a real bug: `Vary: Origin` on the preview's assets
  meant module-script requests missed the cache, so lookups now use `ignoreVary: true`.
- Bundle budget: 196.55 kB / 200 kB JS, 16.76 kB / 20 kB CSS. Note Lighthouse 12 removed the PWA
  category, so installability was verified with the checks above instead; the manual procedure is in
  [`docs/pwa.md`](../../docs/pwa.md).
- Cache strategy, update lifecycle, backup format, threat model and limits are documented in
  `docs/pwa.md` and linked from `docs/architecture.md` and `README.md`.
- Tests: `src/lib/__tests__/backup.test.ts` (shape, round-trip, wrong passphrase, tampering,
  randomness, no plaintext leakage). The worker itself is verified against the preview build, since
  jsdom has no `CacheStorage`/`ServiceWorkerContainer`.
